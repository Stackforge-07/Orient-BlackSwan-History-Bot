# Requirements intake

Fill before planning (copy into the conversation, not a new file, unless the brief is long).

- [ ] **Required features** — numbered R1…Rn, wording from the brief.
- [ ] **Optional / bonus** features — listed separately, built last.
- [ ] **Deliverables** — source repo · README · screenshots · report/PDF · demo video · deployed URL · viva notes.
- [ ] **Stack constraints** — language, framework, DB named? "Must not use…"?
- [ ] **Environment** — offline? lab machine? Node/Python/Docker installed? (`which node python3 docker`)
- [ ] **Data** — entities + fields + relations; sample/seed data needed?
- [ ] **Users & roles** — who logs in; what each role can do.
- [ ] **External services** — AI/API keys available? free tier enough?
- [ ] **Time** — deadline / hours available.
- [ ] **Acceptance** — how will it be judged? (rubric items map to R-numbers)
- [ ] **Ambiguities** — each with the assumption taken.
